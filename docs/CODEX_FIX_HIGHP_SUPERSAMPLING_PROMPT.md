# Codex Fix Task (t_6531a656): Video Anti-Aliasing (highp UV Precision & 1.3x Supersampling Toggle)

You are implementing video anti-aliasing fixes in Arc VR Player (`/root/daydream-vr-player`):
1. Upgrading `VideoShaders.kt` to `precision highp float` for UV interpolation and sampling (eliminating 10-bit half-float quantization staircasing).
2. Adding a user-facing `Supersampling` setting toggle (`1.15x Standard` vs `1.3x High Quality`) with full state persistence, Settings UI integration, and `ThermalGovernor` safety throttling.

---

## 1. Problem & Root Causes

### A. 10-Bit UV Quantization Staircasing in `VideoShaders.kt`
- In `vrcore/src/main/java/com/daydreamvr/vrcore/render/shaders/VideoShaders.kt`, the cinema video fragment shader currently declares:
  `precision mediump float;`
- On mobile GPUs (Qualcomm Adreno, ARM Mali), `mediump` is 16-bit half-float (`fp16`) with only a **10-bit mantissa** (~1,024 discrete steps across `[0.0, 1.0]`).
- For 1080p, 4K, or 8K video, 1,024 steps is coarser than the actual video pixel grid. Adjacent screen fragments get quantized to the same texel and then jump in steps, turning straight diagonal lines into jagged vibrating staircases as the headset moves.
- `FISHEYE_FRAGMENT`, `DistortionShaders`, and `GroundShaders` already use `precision highp float;`. `VideoShaders` standard cinema vertex and fragment shaders must also use `highp` for `vUv` and `vEyeUv`.

### B. Supersampling Option for Texture Minification Shimmer
- Because `GL_TEXTURE_EXTERNAL_OES` cannot have mipmaps generated by OpenGL ES, minified video textures only use bilinear filtering (`GL_LINEAR`).
- Bumping the offscreen eye buffer render scale from `1.15x` to `1.30x` acts as full-scene Super-Sample Anti-Aliasing (SSAA), smoothing minified video edges during the distortion resolve downsample.
- Because `1.30x` has a thermal/power cost, it should be an explicit user toggle in Settings (`Supersampling`: `1.15x (Standard)` vs `1.3x (High)`), wired into `ThermalGovernor` so if the phone heats up (`THERMAL_MODERATE` or higher), it gracefully throttles down to protect the battery and device.

   ```kotlin
   fun qualityFor(
       thermalStatus: Int,
       batteryPercent: Int,
       supersampling: Boolean = false,
   ): Quality {
       val baseScale = if (supersampling) 1.30f else 1.15f
       val thermal = when (thermalStatus.coerceIn(THERMAL_NONE, THERMAL_SHUTDOWN)) {
           THERMAL_NONE, THERMAL_LIGHT -> Quality(renderScale = baseScale, msaa = 4, chromatic = true)
           THERMAL_MODERATE -> Quality(renderScale = 1.0f, msaa = 0, chromatic = true)
           THERMAL_SEVERE -> Quality(renderScale = 0.85f, msaa = 0, chromatic = false)
           else -> Quality(renderScale = 0.7f, msaa = 0, chromatic = false)
       }

       if (batteryPercent in 0 until LOW_BATTERY_PERCENT) {
           return thermal.copy(
               renderScale = minOf(thermal.renderScale, 0.85f),
               msaa = 0,
           )
       }
       return thermal
   }
   ```
